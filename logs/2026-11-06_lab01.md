# Lab 01 — Installing and opening the Unitree Go2 simulation

**Date:** 2026-11-06  
**Goal:** Get Gazebo Harmonic and Unitree Go2 running smoothly in WSL.  
**Status:** Go2 appeared in the simulator; movement via ROS 2 not yet verified in this session.

## Verified environment

- Ubuntu 24.04
- ROS 2 Jazzy (`echo $ROS_DISTRO` yielded `jazzy`)
- Gazebo Sim 8.15.0 (`gz sim --version`)
- Initial renderer: Mesa llvmpipe — `Accelerated: no`
- Forced renderer: `GALLIUM_DRIVER=d3d12` — `D3D12 (Intel(R) Iris(R) Xe Graphics)`, `Accelerated: yes`
- `GALLIUM_DRIVER=d3d12 gz sim -v 4 shapes.sdf --render-engine ogre` ran without noticeable lag.
- Unitree Go2 was visible in Gazebo using the earlier installed simulation project.

## How the performance issue was diagnosed

The graphics capability check showed that OpenGL initially used CPU-based llvmpipe. Forcing Mesa's d3d12 driver enabled Intel Iris Xe acceleration. Selecting `--render-engine ogre` avoided the graphics issues seen when Gazebo loaded `gz-rendering-ogre2`.

## Exact working single-world command

```bash
source /opt/ros/jazzy/setup.bash
GALLIUM_DRIVER=d3d12 gz sim -v 4 shapes.sdf --render-engine ogre
```

## Robot simulation launch

The Go2 launch file was modified in earlier steps to request `--render-engine ogre` instead of the default OGRE2, and the lightweight sensor flags were used. Verify the current local diff before assuming the patch persists.

```bash
source /opt/ros/jazzy/setup.bash
source ~/go2_ws/install/setup.bash
GALLIUM_DRIVER=d3d12 ros2 launch unitree_go2_sim unitree_go2_launch.py \
  rviz:=false disable_camera:=true disable_d455:=true \
  disable_lidar_l1:=true disable_velodyne_lidar:=true
```
